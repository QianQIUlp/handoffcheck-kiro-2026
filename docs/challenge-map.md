# Kiro University Challenge 2026: requirement map

This map records the challenge requirements for HandoffCheck. It is a build checklist, not a claim that any lesson has been completed or any credits have been awarded. Checked on 2026-09-28 against the [challenge page](https://kiro.dev/2026/university/), [official terms](https://kiro.dev/2026/university/terms/), and the live [Final entry form](https://kiro.dev/2026/university/submit/).

## The 5,000-credit route

| Item in the official Final form | Credits | Evidence to produce in this project |
|---|---:|---|
| Lesson 1: Spec-driven development | 250 | Native Kiro feature spec with requirements, design, tasks, and implementation trace. |
| Lesson 2: Steering documents | 250 | Project steering loaded during Kiro development and reflected in the implementation. |
| Lesson 3: Hooks | 250 | Project hook configuration plus an observed trigger and result. |
| Lesson 4: Property-based testing | 500 | Kiro IDE Correctness workflow, executable properties, and actual test results. |
| Lesson 5: Powers | 500 | Valid Power package, local installation, activation, and use on a fresh synthetic case. |
| Lesson 6: MCP | 1,000 | Restricted MCP configuration and an actual tool call used for project work. |
| Lesson 7: Custom agents | 1,000 | Dedicated review agent and an actual run with a substantive review result. |
| All seven required lessons | 1,000 | All seven independently demonstrated in the single Final submission. |
| Free Bonus Lesson 2: Package a Kiro power | 250 | Packaged Power with `plugin.json` and any needed skills/resources/MCP, a public GitHub URL to its `plugin.json`, and installation from the published location. |
| **Target** | **5,000** | Graded by the organizer; local verification cannot guarantee an award. |

Bonus Lesson 1 concerns paid-plan Kiro Web/cloud capabilities and is outside the zero-cash 5,000-credit route. The current Final form supplies the lesson numbering above. Kiro's official [September 23 X post](https://x.com/kirodotdev/status/2102842943933448356) and [September 24 X post](https://x.com/kirodotdev/status/2103152492234072502) use a different L5–L7 order; this project will demonstrate all three capabilities and answer the fields as they appear in the Final form. The [Power creation documentation](https://kiro.dev/docs/powers/create/) specifies the manifest and local import flow; the [installation documentation](https://kiro.dev/docs/powers/installation/) describes import from public GitHub. [Correctness documentation](https://kiro.dev/docs/specs/correctness/) identifies property-based testing as an IDE capability.

## Final submission conditions

- Build a working new project with Kiro as the primary development tool. The public GitHub repository must be owned by the entrant, include relevant `.kiro` files, and have no commit before 2026-09-21 09:00 PT.
- Publish a real 30-second to 3-minute demonstration that shows the project working and how lessons were used. Material after three minutes is not judged.
- Publish one X or LinkedIn post with the public repository, publicly accessible video, a matching 2–3 sentence project description, `#KiroUniversity`, `#BuildWithKiro`, and the platform's required Kiro tag.
- Submit the official Final form with repository, video, live social post, and a writeup of each incorporated lesson by 2026-10-05 23:59 PT (2026-10-06 15:59 JST). The form also requests personal eligibility declarations and account/contact details; those require the entrant's accurate confirmation before submission.
- Eligibility includes age 18+, a GitHub account at least three months old, a Kiro account, one matching X or LinkedIn account, individual single entry, and no excluded residence or AWS employee/family/household relationship. The Final form also asks the entrant to grant a broad perpetual worldwide royalty-free license to the submitted materials. The entrant must personally confirm these facts and rights.
- After the deadline, do not add repository commits before judging ends or an award email arrives, whichever happens first. This project will freeze its public commit at submission.

See the [official terms](https://kiro.dev/2026/university/terms/) for eligibility, disqualification, award, and redemption rules. Public release and Final submission remain pending separate authorization and actual working evidence.
